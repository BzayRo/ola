🛸 2. Introducción

En este trabajo práctico se analiza el video tutorial "Supabase, Tutorial Práctico y Overview (REST API)" del canal Fazt Code. En el material se explican las herramientas BaaS en la nube, el uso de bases de datos PostgreSQL y cómo consumir la API REST autogenerada para construir proyectos web rápidamente.

✨ 3. Conceptos Fundamentales

BaaS (Backend as a Service)

Servicio en la nube que gestiona la base de datos y el servidor para que no tengas que programarlos desde cero.

PostgreSQL

Base de datos relacional potente y segura que organiza la información en tablas conectadas entre sí.

API REST

Conjunto de enlaces web que permiten guardar, consultar y borrar datos en formato JSON mediante peticiones HTTP.

Row Level Security (RLS)

Sistema de seguridad de PostgreSQL que controla qué usuarios pueden ver o editar filas específicas.

☄️ 4. Cuestionario Resuelto (12 Preguntas)

1. ¿Cuál es el tema principal del video? Explica de qué trata.

Trata sobre Supabase, una plataforma que sirve como alternativa a Firebase. Muestra de forma práctica cómo crear una base de datos PostgreSQL en la nube y cómo consultar su API REST automática usando Thunder Client.

2. ¿Qué problema o necesidad tecnológica se aborda?

Resuelve el problema de no tener que programar un servidor (backend) desde cero ni configurar manualmente la base de datos para cada aplicación web.

3. ¿Cuáles son los cinco conceptos más importantes? Define cada uno.

BaaS (Backend en la nube), PostgreSQL (Base de datos relacional), API REST (Enlaces HTTP para JSON), Row Level Security (Seguridad por filas) y API Keys (Claves de acceso de la API).

4. ¿Qué herramientas, programas o tecnologías se mencionan y para qué sirven?

Supabase (Servicios backend), PostgreSQL (Motor de base de datos), VS Code y Thunder Client (Editor y cliente HTTP) y PostgREST (Generador automático de la API).

5. ¿Qué procedimientos o pasos se explican? Preséntalos en orden.

  1. Crear cuenta y proyecto en Supabase.
  2. Diseñar tablas en el Table Editor con sus columnas e IDs.
  3. Ajustar las reglas de RLS para permitir accesos.
  4. Copiar la URL del proyecto y la anon API key.
  5. Probar peticiones GET, POST, PATCH y DELETE con las cabeceras de autenticación en Thunder Client.

6. ¿Qué ejemplos prácticos aparecen? Explica uno detalladamente.

Se crea la tabla tasks. En Thunder Client se hace una petición POST a la URL de la API con las cabeceras de seguridad y enviando en JSON {"title": "Estudiar para el examen", "is_complete": false}, guardando el dato en tiempo real.

7. ¿Qué conocimientos previos son necesarios para comprender lo explicado?

Bases de datos relacionales básicas, métodos HTTP (GET, POST), formato de datos JSON y uso de cabeceras de autenticación.

8. ¿Qué ventajas o beneficios ofrece la tecnología o procedimiento?

Ahorra mucho tiempo de desarrollo, la documentación de la API se crea automáticamente y es una herramienta open source flexible.

9. ¿Qué dificultades, errores o precauciones deben considerarse?

Tener cuidado si el RLS bloquea las consultas por falta de permisos y no exponer la clave secreta service_role en la web.

10. ¿Cómo aplicarías lo aprendido en un proyecto informático real?

Lo aplicaría para crear la base de datos de una web escolar o un sistema de inventarios, conectando el diseño en HTML/JavaScript directamente con Supabase mediante fetch.

11. ¿Qué parte del video consideras más importante y por qué?

La sección donde se realizan las peticiones HTTP en Thunder Client agregando las cabeceras apikey y Authorization, ya que enseña cómo se comunican la web y la base de datos.

12. ¿Qué conocimientos nuevos adquiriste y cómo los explicarías a otra persona?

Aprendí cómo Supabase genera una API REST al instante. Lo explicaría diciendo: "Es un panel donde dibujas tu tabla como en Excel y te da enlaces para guardar o borrar datos desde tu código".
